# 05 · 下载与调试（CLion 内置 ST-LINK）

> 适用版本：CLion 2026.1 / 2026.2 · STM32CubeCLT 1.22.0 · 板载 STLINK-V3EC
> 前置条件：已完成 [03-CubeMX2创建工程](03-CubeMX2创建工程.md)，工程能编译出 `.elf`
> 验证方式：CLion 点击 Debug 后 Console 出现 `Debugger connected to ST-LINK`，程序停在断点

> 本仓库**不使用 OpenOCD**。下载与调试统一使用 CLion 自带的 ST-LINK 支持；
> 只有无图形界面（CI、远程终端）时才用 `STM32_Programmer_CLI` 兜底。

## 1. CLion 内置 ST-LINK 的位置

| CLion 版本 | 菜单路径 |
| --- | --- |
| 2026.2+ | `Settings > Build, Execution, Deployment > Debugger > Debug Profiles` → **ST-LINK** 图块 |
| 2026.1 | `Settings > Build, Execution, Deployment > Debugger > Debug Servers` → `+` → **ST-LINK** 模板 |

如果 2026.1 里看不到 Debug Servers 页，先在 `Settings > Advanced Settings > Debugger` 勾选 **Enable Debug Servers**。

CLion 的 ST-LINK 模板本质上是调用 `ST-LINK_gdbserver`（ST 官方 GDB server），与你手写 OpenOCD 脚本是两条互不依赖的路径。

## 2. 配置 ST-LINK 调试（2026.1 为例）

1. `Settings > Build, Execution, Deployment > Debugger > Debug Servers`，点 `+`。
2. 选择 **ST-LINK** 模板，按下表填写：

| 字段 | 值 |
| --- | --- |
| Name | `NUCLEO-C542RC ST-LINK` |
| ST-LINK GDB server | `/opt/ST/STM32CubeCLT_1.22.0/STLink-gdb-server/bin/ST-LINK_gdbserver` |
| Programmer path（`-cp`） | `/opt/ST/STM32CubeCLT_1.22.0/STM32CubeProgrammer/bin` |
| Interface | **SWD** |
| Device / Target | `STM32C542RCT6`（或由 CLion 从工程推断） |
| Debugger | `/opt/ST/STM32CubeCLT_1.22.0/GNU-tools-for-STM32/bin/arm-none-eabi-gdb` |
| Executable | `build/debug/<PROJECT>.elf` |
| Download | **Always**（每次启动调试都下载） |
| Port | `61234`（默认即可，冲突时改） |

3. 点 **OK**，回到主界面，工具栏选择该调试 profile。

> ⚠️ 未实测：ST-LINK 模板的具体字段名在不同小版本间略有差异；核心是 GDB server 路径、`-cp`、SWD、可执行文件和下载策略五项。
> 若模板默认去找 STM32CubeIDE 内的 GDB server，把路径改到上面的 CubeCLT 版本即可。

## 3. 下载并调试

1. 在 `main()` 里打断点。
2. 点 **Debug**（`Ctrl + D`）。
3. 预期：
   - Console 显示 `Debugger connected to ST-LINK`；
   - 程序停在断点；
   - 点继续后 LD1 按固件逻辑闪烁。

调试期间可用：

- **Variables / Watches**、**Registers**、**Memory**；
- **Peripherals**：需要 SVD，见 [04](04-CLion导入编译调试.md) 第 6 节；
- **Live Watches**：ST-LINK 支持（CLion 提示 Live watches 仅支持 SEGGER J-Link 与 ST-LINK）。

## 4. 只下载、不调试

- 在 CLion 里用同一套 ST-LINK 配置，把启动方式改成 **Run**（不挂断点即等同下载运行）。
- 或者用命令行兜底：

```bash
CUBECLT=/opt/ST/STM32CubeCLT_1.22.0
$CUBECLT/STM32CubeProgrammer/bin/STM32_Programmer_CLI \
  -c port=SWD freq=4000 \
  -w build/debug/<PROJECT>.elf -v -rst
```

常用变体：

```bash
# 整片擦除（谨慎）
... -c port=SWD -e all

# 指定探针序列号（多板同时连接时）
... -c port=SWD sn=<STLINK_SN>

# 降低速度排查接触不良
... -c port=SWD freq=1000
```

> ⚠️ **不要随意改 option bytes / RDP**，改错可能导致芯片锁死。

## 5. 串口查看

```bash
ls /dev/cu.usbmodem*                       # VCP 设备
screen /dev/cu.usbmodemXXXX 115200         # 退出：Ctrl-A，K，y
```

- VCP 走 **USART2（PA2/PA3）**，出厂 SB12/SB26 已短接。
- 固件需先初始化 USART2，否则没有输出。
- 找不到设备：换数据线、确认 CN1、看 `system_profiler SPUSBDataType`。

## 6. 为什么不用 OpenOCD

- CLion 的 ST-LINK 模板直接调用 ST 官方 GDB server，配置更少、与 CubeCLT 版本一致。
- 当前 OpenOCD（0.12 与上游）没有 STM32C5 的 target 文件，无法用于本板卡。
- 两套工具并存容易造成“探针被占用”的假故障，仓库只保留一条主线。

## 7. 批量 / CI 提示

- 无 GUI 环境用 `STM32_Programmer_CLI`，命令见第 4 节。
- CI 中避免 `-e all` 之外的全片擦除，不要改 option bytes。
- macOS 服务器需要已登录的图形会话才能访问 USB 探针；Linux 需要 udev 规则。

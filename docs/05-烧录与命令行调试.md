# 05 · 烧录与命令行调试

> 适用版本：STM32CubeCLT 1.22.0 · STLINK-V3EC · macOS
> 前置条件：已编译出 `.elf`；板子通过 CN1 连接电脑
> 验证方式：下载后复位，LD1 按固件逻辑闪烁；`STM32_Programmer_CLI -l` 能看到探针

## 1. 用 STM32CubeProgrammer CLI 烧录

```bash
CUBECLT=/opt/ST/STM32CubeCLT_1.22.0
ELF=build/<PROJECT>.elf

# 列出探针
$CUBECLT/STM32CubeProgrammer/bin/STM32_Programmer_CLI -l

# 下载 ELF 并校验、复位运行
$CUBECLT/STM32CubeProgrammer/bin/STM32_Programmer_CLI \
  -c port=SWD freq=4000 \
  -w "$ELF" -v -rst
```

常用变体：

```bash
# 整片擦除（会清掉所有扇区，谨慎）
... -c port=SWD -e all

# 只写 .bin（需要显式给地址，C5 Flash 起始 0x08000000）
... -c port=SWD -w firmware.bin 0x08000000 -v -rst

# 读回校验 / 读保护等 option bytes：先查询再改，改错可能导致芯片锁死
... -c port=SWD -ob RDP=0xAA
```

> ⚠️ **不要随意改 option bytes / RDP**，尤其是 RDP Level 1 以上，可能触发整片擦除或锁死。

## 2. 指定探针 / 连接方式

```bash
# 多探针时按序列号选择
... -c port=SWD sn=<STLINK_SN>

# 连接速度（kHz），排线长或信号差时降低
... -c port=SWD freq=1000

# 复位方式：硬件复位 / 软件复位
... -c port=SWD mode=UR    # 连接时保持复位
... -c port=SWD mode=normal
```

## 3. 用 GDB 手动调试

CLion 背后就是这套组合，排查时可以单独跑：

```bash
# 终端 1：启动 GDB server（监听 61234）
cd /tmp && /opt/ST/STM32CubeCLT_1.22.0/STLink-gdb-server/bin/ST-LINK_gdbserver \
  -cp /opt/ST/STM32CubeCLT_1.22.0/STM32CubeProgrammer/bin \
  -d -p 61234

# 终端 2：连接并加载程序
/opt/ST/STM32CubeCLT_1.22.0/GNU-tools-for-STM32/bin/arm-none-eabi-gdb build/<PROJECT>.elf \
  -ex "target remote :61234" \
  -ex "monitor reset halt" \
  -ex "load" \
  -ex "monitor reset run"
```

常用命令：

| 命令 | 作用 |
| --- | --- |
| `load` | 下载 ELF 到 Flash |
| `monitor reset halt` / `monitor reset run` | 复位停住 / 复位运行 |
| `info registers` | 查看寄存器 |
| `x/16xw 0x08000000` | 查看 Flash 起始内容 |

## 4. OpenOCD 的现状（重要）

本机 OpenOCD 0.12.0（Homebrew）与上游 master **都没有 `stm32c5x.cfg`**，直接使用会报：

```text
Error: open failed / unknown target 'stm32c5x.cfg'
```

因此：

- **STM32C5（含 C542）请使用 ST-LINK GDB server 或 STM32CubeProgrammer**（如上两节）。
- `templates/openocd/nucleo-c542rc.cfg` 是前瞻模板，等 OpenOCD 合并 C5 支持后再启用。
- 判断是否支持：

```bash
openocd -f interface/stlink.cfg -f target/stm32c5x.cfg -c "init; shutdown" 
# 若报找不到 target 文件，说明版本还不支持
```

## 5. 串口查看

```bash
ls /dev/cu.usbmodem*                       # VCP 设备通常是 usbmodem 开头
screen /dev/cu.usbmodemXXXX 115200         # 退出：Ctrl-A，K，y
```

- VCP 走 **USART2（PA2/PA3）**，出厂 SB12/SB26 已短接。
- 固件里要先初始化 USART2（CubeMX2 里启用 USART2 → Asynchronous），否则串口无输出。
- 找不到设备时：换数据线（有些线只有供电）、检查 CN1 是否插在电脑上、看 `system_profiler SPUSBDataType`。

## 6. 批量 / CI 提示

- 编译用 `<CubeCLT>/CMake/bin/cmake` + Ninja，产物路径固定后可直接接 `STM32_Programmer_CLI`。
- 服务器上跑需要 udev 规则（Linux）或已登录图形会话（macOS 的 USB 权限）。
- CI 里不要做 `-e all` 之外的全片擦除；也不要改 option bytes。

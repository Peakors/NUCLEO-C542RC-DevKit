# 02 · 环境搭建（macOS）

> 适用版本：STM32CubeMX2 1.1.2 · STM32CubeCLT 1.22.0 · CLion 2026.1/2026.2 · macOS 15/26
> 前置条件：Apple Silicon Mac，至少有 8 GB 空闲磁盘（建议 20 GB），能访问 st.com 与 GitHub
> 验证方式：第 6 节的四条命令全部输出正常

## 1. 组件与版本

| 组件 | 作用 | 本文档版本 |
| --- | --- | --- |
| **STM32CubeMX2** | 图形化配置 + 生成 CMake 工程 | 1.1.2 |
| **STM32CubeCLT** | 命令行工具集：GCC、CMake、Ninja、GDB、ST-LINK GDB server、CubeProgrammer | 1.22.0 |
| **CLion** | 编辑、编译、调试 | 2026.1 / 2026.2 |
| ST-LINK 驱动 | 板载 STLINK-V3EC，macOS 免驱 | 系统自带 |

> 经典版 STM32CubeMX（6.x，`.ioc` + 老式工程结构）与本流程不兼容，本仓库不采用。两者可以共存，但不要混用同一个工程。

## 2. 安装 STM32CubeMX2

1. 打开 ST 的 CubeMX 产品页：<https://www.st.com/en/development-tools/stm32cubemx.html>，选择 **STM32CubeMX2** 下载 macOS 安装包（需要 ST 账号）。
2. 支持 macOS 15 与 macOS 26（Intel 与 Apple Silicon 均可），**不需要管理员权限**，安装到用户目录即可。
3. 首次启动会要求安装设备包（Device Pack）与 HAL 包，按向导联网下载；C5 系列包较大，预留足够空间。
4. 在 `Settings > Preferences` 中确认 Pack 安装目录；默认位置会随工程生成 `misc/` 目录（已加入 `.gitignore`）。

> ⚠️ 未实测：本机只装了经典版 CubeMX 6.18，CubeMX2 的安装向导界面未逐屏验证。以上步骤依据官方文档 1.1.2 的 Installation 章节。

## 3. 安装 STM32CubeCLT

本机已安装，路径固定为：

```bash
/opt/ST/STM32CubeCLT_1.22.0
```

若需在新机器安装，从 <https://www.st.com/en/development-tools/stm32cubeclt.html> 下载 macOS 版本并安装到同一路径（或自行记录路径，后续命令替换即可）。

关键路径：

```text
<CubeCLT>/GNU-tools-for-STM32/bin/arm-none-eabi-gcc
<CubeCLT>/GNU-tools-for-STM32/bin/arm-none-eabi-gdb
<CubeCLT>/CMake/bin/cmake
<CubeCLT>/Ninja/bin/ninja
<CubeCLT>/STLink-gdb-server/bin/ST-LINK_gdbserver
<CubeCLT>/STM32CubeProgrammer/bin/STM32_Programmer_CLI
<CubeCLT>/STMicroelectronics_CMSIS_SVD/STM32C542.svd
```

## 4. 安装并配置 CLion

1. 安装 CLion 2026.1 或更新版本。
2. 打开 `Settings > Build, Execution, Deployment > Toolchains`：
   - **方案 A（推荐）**：如果列表里有 **STM32CubeCLT** 类型，直接选择本机安装目录 `/opt/ST/STM32CubeCLT_1.22.0`。
   - **方案 B**：新建 `System` 工具链，把 CubeCLT 的 `bin` 目录加到环境变量 `PATH`，并显式指定：
     - C 编译器：`<CubeCLT>/GNU-tools-for-StM32/bin/arm-none-eabi-gcc`
     - C++ 编译器：`<CubeCLT>/GNU-tools-for-STM32/bin/arm-none-eabi-g++`
     - 调试器：`<CubeCLT>/GNU-tools-for-STM32/bin/arm-none-eabi-gdb`
     - CMake：`<CubeCLT>/CMake/bin/cmake`
     - Ninja：`<CubeCLT>/Ninja/bin/ninja`
3. 如果使用 Cube CLI 管理工具版本，确认 `cube` 在 PATH 中；CLion 会在
   `Settings > Build, Execution, Deployment > Embedded Development > STM32` 里显示检测结果。

> ⚠️ 未实测：CLion 不同小版本对 STM32CubeCLT 工具链的识别方式略有差异；若方案 A 不出现，按方案 B 手动填写即可。

## 5. 检查 ST-LINK

板载 STLINK-V3EC 免驱，插上 CN1 后 macOS 直接识别：

```bash
# 应能看到 STMicroelectronics STLINK 设备
system_profiler SPUSBDataType | grep -A6 -i "ST-LINK\|STLINK"

# 列出已连接的 ST-LINK
/opt/ST/STM32CubeCLT_1.22.0/STM32CubeProgrammer/bin/STM32_Programmer_CLI -l
```

预期：输出中能看到 STLINK-V3EC 的序列号与固件版本。

## 6. 验证安装

```bash
/opt/ST/STM32CubeCLT_1.22.0/GNU-tools-for-STM32/bin/arm-none-eabi-gcc --version | head -1
# arm-none-eabi-gcc (GNU Tools for STM32 14.3.rel1...) 14.3.1

/opt/ST/STM32CubeCLT_1.22.0/CMake/bin/cmake --version | head -1
# cmake version 4.3.1（CubeMX2 要求 ≥ 3.30）

/opt/ST/STM32CubeCLT_1.22.0/STM32CubeProgrammer/bin/STM32_Programmer_CLI -l
# 能看到 STLINK-V3EC

open -a CLion
# 能正常启动，Toolchains 中没有红色报错
```

## 7. 串口终端

macOS 自带 `screen`，也可以装 `picocom`：

```bash
ls /dev/cu.usbmodem*          # 找到 VCP 设备
screen /dev/cu.usbmodemXXXX 115200   # 退出：Ctrl-A 然后 K
```

# 06 · 常见问题

> 适用版本：CubeMX2 1.1.2 · CubeCLT 1.22.0 · CLion 2026.1/2026.2 · macOS
> 前置条件：无
> 验证方式：按条目处理后，对应步骤能通过

## 环境与工具

### Q1. CLion 报 `CMake 3.30 or higher is required`

**现象**：CMake reload 失败，提示版本过低。
**原因**：CubeMX2 要求 CMake ≥ 3.30，CLion 或系统默认的 CMake 太旧。
**处理**：把 CMake profile 的 CMake 路径显式设为 `<CubeCLT>/CMake/bin/cmake`（本机 4.3.1），或在 `Settings > Build, Execution, Deployment > CMake` 里选 CubeCLT 的 CMake。

### Q2. CLion 找不到 `arm-none-eabi-gcc`

**现象**：Toolchain 里编译器路径标红。
**原因**：没有把 CubeCLT 加入工具链，或 PATH 里是 Homebrew 的旧工具链。
**处理**：`Settings > Toolchains` 新建 `System`，手动填 `<CubeCLT>/GNU-tools-for-STM32/bin/arm-none-eabi-gcc`、`...-g++`、`...-gdb`，CMake/Ninja 指向 CubeCLT 对应目录。

### Q3. macOS 提示“无法打开 STM32CubeMX2，因为无法验证开发者”

**现象**：双击应用被系统拦截。
**原因**：Gatekeeper 拦截未公证的安装包。
**处理**：`系统设置 > 隐私与安全性`，在下方点 **仍要打开**；或右键应用 → 打开。不要用 `sudo spctl --master-disable`。

### Q4. CubeMX2 安装后找不到板卡 NUCLEO-C542RC

**现象**：Board 列表里没有 C5 板卡。
**原因**：C5 的 Device Pack / HAL Pack 未安装，或 CubeMX2 版本过旧。
**处理**：打开 **Pack Manager** 安装/更新 STM32C5 系列包；仍不行就升级 CubeMX2 到 1.1.2 或更新版本。

## 连接与烧录

### Q5. `STM32_Programmer_CLI` 报 “No ST-LINK detected”

**现象**：`-l` 或连接时找不到探针。
**原因**：线材只有供电没有数据、CN1 未接、探针被其他程序占用、USB Hub 供电不足。
**处理**：换一根确认能传数据的 Type-C 线；直连电脑；关闭 STM32CubeProgrammer 图形界面、CLion 调试会话等占用探针的程序；`system_profiler SPUSBDataType` 确认设备存在。

### Q6. 下载成功但程序不运行

**现象**：烧录显示成功，LD1 不闪。
**原因**：BOOT0 被拉高（B3 卡住）、复位未释放、时钟配置错误导致卡在 `HAL_Init`、链接脚本/启动文件与芯片不匹配。
**处理**：确认 B3 没有被按下；`-rst` 复位后观察；用调试器停在 `main` 看是否进入；检查生成的工程是否选对 STM32C542RCT6。

### Q7. CLion 的 ST-LINK 连不上 / 下载失败

**现象**：点击 Debug 后卡住，或 Console 报 `Debugger connected` 之后无法下载、报 “no target”。
**原因**：ST-LINK GDB server 路径不对、`-cp` 指向错误、探针被其他程序占用、SWD 速度过高、板子没供电。
**处理**：
1. `Settings > ... > Debugger > Debug Servers/Profiles` 里确认 GDB server 指向 `<CubeCLT>/STLink-gdb-server/bin/ST-LINK_gdbserver`，`Programmer path` 指向 `<CubeCLT>/STM32CubeProgrammer/bin`。
2. 关闭 CubeProgrammer 图形界面、其他调试会话，确保只有一个程序占用 ST-LINK。
3. 把 GDB server 参数加 `--frequency 1000` 降低 SWD 速率。
4. 确认 CN1 接在电脑上、USB 线能传数据；`STM32_Programmer_CLI -l` 能看到探针。
5. 仍失败时用 [05](05-下载与调试.md) 的命令行方式验证硬件通路，再回到 CLion。

> 本仓库不使用 OpenOCD；不要通过安装/配置 OpenOCD 来“解决”这类问题。

## 工程生成

### Q8. 重新生成代码后 `CMakeLists.txt` 的手工修改丢了

**现象**：CubeMX2 再次 Generate 后，自己加的源文件/编译选项消失。
**原因**：CubeMX2 不合并 IDE 工程文件（官方限制）。
**处理**：把源文件与配置写进 `.ioc2` 的工程设置；或把业务代码放进独立目录，通过生成器支持的“用户文件”机制登记；每次生成前先 `git status` 确认改动。

### Q9. 更新 pack 后编译报错

**现象**：之前能编译，pack 升级后大量 `undefined reference` / 头文件找不到。
**原因**：CubeMX2 创建工程时默认用最新 pack，API 可能变化。
**处理**：删除 `build/` 与 CMake cache 重新生成；在 **Packs details** 里回退到上一个可用版本；必要时固定 pack 版本（官方提供脚本）。

### Q10. 工程路径包含空格或中文

**现象**：生成失败、CMake 报错、调试器找不到文件。
**原因**：CubeMX2、CMake、GDB 对路径敏感。
**处理**：工程放在纯英文、无空格的路径下，例如 `~/STM32Project/NUCLEO-C542RC-DevKit/projects/blink_led`。

## 硬件

### Q11. 串口没有输出

**现象**：VCP 打开后没有数据。
**原因**：固件没初始化 USART2、波特率不匹配、SB12/SB26 被断开、接了 Arduino 扩展板占用 PA2/PA3。
**处理**：确认 CubeMX2 里 USART2 已启用且引脚为 PA2/PA3；波特率一致；检查 SB12/SB26；换 `screen`/`picocom` 试。

### Q12. 按下 B1 后板子异常 / 复位

**现象**：按下用户按键后程序跑飞或电流异常。
**原因**：PC13 被配置成输出并驱动低电平——UM3615 明确禁止（会短路）。
**处理**：把 PC13 配置为**输入**（可开内部上拉/下拉或依赖外部下拉），不要设为输出。

### Q13. LD1 不亮但程序在跑

**现象**：调试能看到程序执行，LED 不亮。
**原因**：PA5 未配置为输出、SB8 断开、LED 由三极管驱动需要高电平、或 PA5 被 SPI1 等外设占用。
**处理**：检查 GPIO 配置与 SB8；确认没有把 PA5 复用成 SPI1_SCK。
